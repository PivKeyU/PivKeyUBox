## 一、方案总览

整改的核心不是把某个控件的数值改对，而是**先定死 5 个值，再让代码和 CI 去守它们**。分三块：

| 块 | 内容 | 阶段 | 工期 |
|---|---|---|---|
| A. 定值 | 5 个决策写进 `ACTIVE.md`，处理掉误导人的 `MASTER.md` | 阶段 0 | 0.5 天 |
| B. 归位 | 令牌层补齐 → 便签页并入系统 → 三个原生窗口接主题 → 菜单契约收口 → 可访问性 → CSS 层收敛 → 资产 | 阶段 1–7 | 8 天 |
| C. 守门 | stylelint 4 条规则 + 令牌一致性单测 + 截图回归 | 阶段 8 | 0.5 天 |

**先做 C 里的一小部分**（令牌一致性单测，20 行）也能立刻受益：它会在下一次"改了 CSS 忘了改原生"时报红。

## 二、需要先拍板的一个产品决策

其余所有工作都取决于这一个分叉，建议先定它。

### 推荐 A：以中性 + 蓝为默认，珊瑚作为可选配色

即：默认强调色 `#3478f6`（调深为 `#1e63e0`，见下），奶油珊瑚作为 `schemeColors.warm` 保留。理由：

1. **它已经是实际默认**：`tokens.css:11`、`src/state/theme.ts:2`、`Manager.cs:335`、`CategoryModal.tsx:10` 都是它，改方向意味着这 4 处加全套 CSS 反向对齐；
2. **对比度更容易达标**：`#1e63e0` 一次改值同时满足"正文色"和"白字底"两个方向（5.36:1）；
3. **`--st-*` 那套中性皮肤已经赢了 CSS 级联**，方向 A 只需归位，方向 B 需要整套替换。

### 备选 B：以吉伊奶油 + 珊瑚为默认

可行，但有两个硬约束必须先接受：

1. **珊瑚不能配白字**：白字在 `#e98687` 上只有 **2.44:1**，`#d56f78` 也只有 3.15:1。走 B 就必须把主按钮/选中态改成**深棕字配珊瑚底**（`--chi-ink #3d302c` on `#e98687` = 4.96:1 通过）；
2. **珊瑚不能作正文色**：`#e98687` 在奶油纸上 2.44:1，最深的 `#b4535c` 才到 4.63:1——即"强调色"和"正文强调色"必须是两个令牌。

工期约为方案 A 的 2.5 倍（详见 §六）。**我的建议是 A**：产品定位不必靠默认色承载，把奶油珊瑚做成用户可选方案，既保住可访问性又保住设计意图。

## 三、五个必须先定下来的值

### 1. 默认强调色：`#3478f6` → `#1e63e0`

| 用途 | `#3478f6`（现状） | `#1e63e0`（建议） |
|---|---|---|
| 作正文色 on `#ffffff` | 4.07 ✗ | **5.36 ✓** |
| 作正文色 on `#f8f9fa`（控件底） | 3.86 ✗ | **5.09 ✓** |
| 白字在其上（主按钮） | 4.07 ✗ | **5.36 ✓** |
| 深色卡片上 on `#2b2825` | 3.60 ✗ | 5.45 ✓ |

**一个令牌改值同时修好四处失败**，这是全项目性价比最高的一处修改。同时这 4 处定义必须收敛到 1 处来源（`tokens.css` 为 CSS 侧、`Manager.cs` 为原生侧），并用单测锁住一致性。

### 2. 中性表面：浅 `#ffffff` / 深 `#22211e`（纸）+ `#2b2825`（卡片）

现状是三套：CSS 设置页 `#201e1c`（`styles.css:3597`）、原生面板/便签 `(34,33,30)` = `#22211e`（`Manager.cs:1870`）、原生胶囊兜底 `(31,31,31)`（`PanelWindow.cs:3042`、`:2949`、`NoteWindow.cs:861`）。

建议**统一到原生正在画的 `#22211e`**（改 CSS 一处 `--st-bg` 深色值即可），因为原生值同时作用在桌面层最显眼的两个窗口上，且 `#201e1c` 只影响设置页背景。

### 3. 字号级差：11 / 12 / 13 / 15 / 20（5 档）

现状 17 个取值、145 处声明、0 处走令牌，其中 5 档挤在 2px 内。

| 档位 | 用途 | 对应现状 |
|---|---|---|
| 11 | 次要说明、提示、徽标 | 10 / 10.5 / 11 / 11.5 收敛 |
| 12 | 行标签、小正文 | 12 / 12.5 收敛 |
| 13 | 正文、菜单、标题栏 | 13 / 13.5 收敛 |
| 15 | 卡片/分组标题（`strong`） | 14 上调 |
| 20 | 页面标题（masthead h3） | 20 保留（现有 3 个 clamp 收敛为 1 个） |

**例外**：面板条目的 `labelSize`（8–14px，`PanelWindow.cs:112`）是用户可调设置，不属于 UI 级差，不要纳入。

> **2026-09-20 已更新（`24a3e24`）**：区间从 [8,14] 改为 **[8,18]，默认 10 → 12**（紧凑模式兑底 11）。"用户可调、不纳入 UI 级差"这个定性**仍然正确且已加强**：旧值 8–11 原样保留、不被强制改写（`boundedNumber` 语义，有回归测试守护）。另：设置页新增「清晰 / 标准 / 紧凑」三档预设（作用于**当前选中分类**），这是从"不纳入级差"到"提供一致预设"的折中。

### 4. 圆角级差：6 / 8 / 12 / 16（+ 999 胶囊）

现有 24 个取值、仅 27/159 走令牌。映射规则：

| 建议档位 | 用途 | 从哪些值收敛 |
|---|---|---|
| 6（新增 `--radius-xs`） | 内嵌小件、菜单悬停胶囊、色点 | 3 / 5 / 6 / 7 |
| 8（`--radius-sm`） | 控件、按钮、输入、菜单容器 | 8 / 9 / 10 |
| 12（`--radius-md`） | 卡片、分组、缩略卡 | 11 / 12 / 13 |
| 16（`--radius-lg`） | 窗口、弹层、模态 | 14 / 15 / 16 / 18 / 20 |

`--radius-xl`（`tokens.css:24`）零引用，删除。

### 5. 菜单行高：36px

这一条不用重新讨论——`README.md:26` 已经把它写成产品契约：

> 分区右键菜单对齐 DeskBox / Win11 MenuFlyout 规范（系统字体 13px、**36px 行高**、16px 图标、8px 菜单圆角、4px 悬停圆角、中性悬停、**强调色勾选**）

代码只在两处违约：

| 契约条款 | 托盘 | 面板菜单 | 便签菜单 |
|---|---|---|---|
| 36px 行高 | 36 ✓（`PivkeyHost.cs:492`） | **32 ✗**（`PanelWindow.cs:1028`） | **30 ✗**（`NoteWindow.cs:1047`） |
| 8px 菜单圆角 | OS 提供 | 8 ✓（`PanelWindow.cs:889`） | 8 ✓（`NoteWindow.cs:1014`） |
| 4px 悬停圆角 | 4 ✓（`PivkeyHost.cs:933`） | 4 ✓（`:1024`） | 4 ✓（`:1072`） |
| **强调色勾选** | n/a | **硬编码 `#3478f6` ✗**（`:865-868`） | 无勾选槽 |
| 13px 系统字体 | 9.5pt ≈ 12.7 ✓ | 13 ✓ | 13 ✓ |

**结论：托盘是唯一完全合规的菜单，面板和便签各自违约 1–2 条。** 整改方向明确——让面板和便签向托盘与 README 看齐。

### 阶段 8：防复发机制（0.5 天）

**这是整个方案里最重要的一步**——过去 8 轮改版都在文件末尾追加覆盖，靠人自觉挡不住第 9 轮。加 CI 守门：

1. **stylelint 4 条规则**：
   - `color-no-hex`（`tokens.css` 例外）
   - `font-size` 只允许 `var(--text-*)`
   - `declaration-no-important`（白名单只留 3 处：`269` 的拖动禁用动画、`1538-1540` 的全局减少动效）
   - `border-radius` 只允许 `var(--radius-*)`
2. **令牌一致性单测**（约 20 行，接进现有 vitest）：断言 `tokens.css` 的 `--color-accent-base`、`theme.ts:2` 的 `schemeColors.white.accent`、`Manager.cs:335` 的 `DefaultCustomColor` 三者相等。这条测试直接防住"改了一个忘了另一个"——正是当前 `#3478f6` 散落 4 处的成因。
3. **截图回归**：设置页 + 面板 + 便签 × 浅色/深色，接进 `npm test` 旁的任务。把"某个值被哪一层覆盖"变成可见的 CI 输出。

## 六、不建议做的事

1. **不要在现有 8 层之上再加第 9 层覆盖。** 这是过去几轮的做法，也正是当前问题的成因——`.modal__header h2` 的字号改了 5 次又绕回 16px，`.segmented button` 的 min-height 绕回 30px，净收益为零。
2. **不要把 Chiikawa 暖色强推到全栈。** `design-review/README.md` 自己写着这是"隔离的视觉审阅稿，不会替换当前 React 界面"，且明确"确认后再进入第二阶段"——第二阶段尚未确认。且珊瑚配白字 2.44:1、配深棕字 4.96:1，两者差距决定了它不是一次换色那么简单。
3. **不要动用户可调的 `labelSize`。** 面板条目字号 8–14px 是用户设置在 `PanelWindow.cs:112`，把它并进 UI 级差会破坏用户配置的语义。

   > **2026-09-20 重申并更新**：区间已放宽到 [8,18]、默认 12（见 §三 标注）。"不要动用户已存的 `labelSize`"这条**依然有效且已被测试锁住** —— 新默认只作用于缺失字段，旧值 8–11 不会被抬到 12。将来若真要把该值并入统一字号级差，必须先推翻 `src/state/preferences.test.ts` 里的 `keeps an existing label size instead of forcing the new default`。
